# Crypto Mispricing Detection Strategy (v2)

> v2 changelog: 修正 barrier vs 终值概率错配、加入 Q→P 校准、成本自适应信号、jump-diffusion 模型、拉长验证周期。

## Overview

Detect mispriced crypto price-target markets on Polymarket by comparing market prices against probability estimates derived from options markets and historical simulation. Trade only when net edge (after costs and uncertainty) is positive.

## Core Thesis

Polymarket crypto markets are largely priced by retail intuition. Professional-grade tools (options-implied barrier probabilities, jump-diffusion simulation) can produce more accurate estimates. The gap between the two, minus trading costs, is our edge.

## Target Markets

**Scope: 仅限纯价格市场，排除事件驱动市场。**

Included:
- "Will BTC reach $X by date Y?" (barrier/touch type)
- "Will ETH reach $X by date Y?" (barrier/touch type)
- Price range / bracket markets (terminal value type)

Excluded (不同信号源，单独建策略):
- ETF approvals, protocol upgrades, regulatory actions
- Any market whose resolution depends on non-price events

**市场分类标签**:
- `barrier_up`: 到期前是否向上触达目标价
- `barrier_down`: 到期前是否向下触达目标价
- `terminal_range`: 到期时价格落在某区间

每种类型使用对应的概率计算方法，不可混用。

## Technical Architecture

### Layer 1: Data Collection

| Source | Data | Purpose |
|--------|------|---------|
| Polymarket API | Market prices, order book depth, volume, bid-ask spread | Current market pricing + cost estimation |
| Deribit API | Options chain (strikes, IVs, prices) for BTC/ETH | Implied probability distribution |
| Binance/Coinbase | Spot + perp prices, funding rates, historical OHLCV | Current price + volatility estimation |
| On-chain (free APIs) | Large transfers, exchange balances | Supplementary directional signal |

### Layer 2: Probability Models

#### Problem Type Distinction (critical)

Polymarket 的 "Will X reach $Y before date T?" 是一个 **first-passage (barrier) 问题**，不是终值问题。

- Barrier 问题: P(max(S_t, 0<=t<=T) >= X) — 路径上任意时刻触达即算
- Terminal 问题: P(S_T >= X) — 仅看到期时刻的价格

Barrier 概率 >= Terminal 概率（永远如此）。用终值概率去估计 barrier 市场会**系统性低估**，产生虚假 edge。

#### Model A - Options-Implied Barrier Probability

1. 从 Deribit 期权链提取隐含波动率曲面 σ(K, T)
2. 用 barrier option 定价公式反推 first-passage 概率
   - 对于 up-and-in barrier: 使用解析公式（连续 barrier 近似）
   - 对于 terminal range: 直接从 vanilla option 价格提取
3. **Q→P 校准**: Deribit 给出的是风险中性概率 (Q-measure)，需要调整到真实概率 (P-measure)
   - 方法: 用历史已 resolve 的 Polymarket 市场做回归校准
   - 收集历史数据: (Q-probability at entry, actual outcome)
   - 拟合校准函数: P_real = f(Q_risk_neutral)
   - 初期数据不足时: 保守处理，对 Q 概率打折（如 ×0.85）作为安全边际

#### Model B - Jump-Diffusion Monte Carlo

GBM 对 crypto 不适用: 忽略肥尾和价格跳跃，尤其对 barrier 问题偏差更大。

使用 Merton Jump-Diffusion 模型:
```
dS/S = (μ - λk)dt + σdW + JdN

其中:
- σ: 扩散波动率 (从历史数据估计)
- λ: 跳跃频率 (从历史大幅波动统计)
- J: 跳跃幅度 (log-normal 分布, 参数从历史估计)
- N: Poisson 过程
```

模拟流程:
1. 从历史数据估计参数 (σ, λ, μ_J, σ_J)
2. 模拟 100K+ 条价格路径
3. **Barrier 市场**: 检查每条路径是否在到期前触达目标价
4. **Terminal 市场**: 检查到期时价格是否在目标区间
5. 输出: 概率估计 + 置信区间

#### Combined Signal

```
P_combined = w_A * P_options_calibrated + w_B * P_jumpdiff

默认权重:
- w_A = 0.6 (期权市场信息更丰富)
- w_B = 0.4 (jump-diffusion 捕捉结构性风险)

当期权市场流动性差时 (bid-ask > 5%): 降低 w_A
当距到期 < 3 天时: 提高 w_A (短期期权定价更准)
```

输出同时包含 **点估计** 和 **不确定性区间** (bootstrap 或模型参数扰动)。

### Layer 3: Signal Generation (Cost-Adaptive)

```python
# 成本估算
fee = polymarket_taker_fee                    # ~2%
slippage = estimate_slippage(order_size, order_book)  # 从订单簿模拟
spread_cost = (ask - bid) / 2                 # 半个 bid-ask spread
total_cost = fee + slippage + spread_cost

# 不确定性缓冲
uncertainty = model_confidence_interval_width / 2  # 模型不确定性

# 净边际
edge_gross = P_combined - polymarket_price    # (for BUY_YES case)
edge_net = abs(edge_gross) - total_cost - uncertainty

# 下单条件: 净边际为正
if edge_net > 0:
    direction = BUY_YES if edge_gross > 0 else BUY_NO
    # Kelly 也用净边际计算，而非毛边际
    kelly_fraction = edge_net / (1 - polymarket_price) if direction == BUY_YES else edge_net / polymarket_price
    position_size = quarter_kelly(kelly_fraction, capital)  # 用 quarter-Kelly 更保守
    emit signal
```

**注意**: 从 half-Kelly 降级为 **quarter-Kelly**，因为:
- 模型不确定性在早期较大
- Crypto 波动率本身不稳定
- 验证阶段目标是证明 edge 存在，不是最大化收益

### Phase 2: Small Live (Week 4-8)

- Quarter-Kelly 仓位

**Week 5-8**: 积累样本

- 每周复盘: 模型校准曲线、成本模型准确度、P&L

### Phase 3: Validation Gate (Week 9-12)

**放大资金的硬性门槛** (全部满足才可):

| 指标 | 门槛 |
|------|------|
| 已 resolve 交易数 | >= 30 笔 |
| 模型校准误差 (Brier Score) | < 0.25 |
| 净 P&L (扣除所有成本) | > 0 |
| 最大回撤 | < 15% |
| 成本模型误差 (预估 vs 实际) | < 2% |
| 校准曲线 | 通过 Hosmer-Lemeshow 检验 (p > 0.05) |

未达标: 继续小资金运行 + 优化模型，不放大。

### Phase 4: Scale (Week 13+)

- 逐步放大: $500 → $2K → $10K → $50K → $100K
- 每次翻倍前重新检查门槛指标
- 关注: 资金增大后滑点是否显著增加（市场深度限制）

## Risk Management

| Rule | Limit |
|------|-------|
| Single position max | 5% of total capital |
| Single asset exposure (all BTC markets combined) | 30% of total capital |
| Drawdown stop | Pause at 15% drawdown, mandatory review |
| Liquidity filter | Skip markets where estimated slippage > 1% |
| Model disagreement | Skip if Model A and B estimates differ > 20% |
| Minimum edge | Only trade when edge_net > 0 (after all costs) |

## Capital Plan

- Validation phase (Week 1-12): $500 - $2,000
- Scale phase (Week 13+): gradual increase to $100,000
- Scale only after passing ALL validation gate criteria
- Each 2x increase requires re-validation of gate metrics

## Key Risks

1. **概率类型错配**: barrier vs terminal 概率混用导致系统性误判 → 已通过市场分类标签解决
2. **Q→P 校准失败**: 历史数据不足导致校准不准 → 用保守折扣 + 逐步积累数据
3. **模型风险**: Jump-diffusion 参数估计偏差 → 用 uncertainty buffer 吸收
4. **流动性风险**: 薄市场滑点吃掉 edge → 流动性过滤 + 实际成本追踪
5. **相关性风险**: 多个 BTC 市场同向暴露 → 单资产敞口上限 30%
6. **平台风险**: Polymarket resolution 争议、API 变更 → 分散到多平台（后期）
7. **政权变化**: Crypto 波动率 regime shift → 滚动窗口重估参数，异常时暂停
