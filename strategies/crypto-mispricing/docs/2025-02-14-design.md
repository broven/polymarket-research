# Crypto Mispricing Detection Strategy

## Overview

Detect mispriced crypto markets on Polymarket by comparing market prices against probability estimates derived from options markets and historical simulation. Trade when divergence exceeds a threshold.

## Core Thesis

Polymarket crypto markets are largely priced by retail intuition. Professional-grade tools (options-implied probabilities, Monte Carlo simulation) can produce more accurate estimates. The gap between the two is our edge.

## Target Markets

Polymarket crypto category, primarily:
- "Will BTC reach $X by date Y?"
- "Will ETH reach $X by date Y?"
- Price range / bracket markets
- Event-driven: ETF approvals, protocol upgrades, regulatory actions

## Technical Architecture

### Layer 1: Data Collection

| Source | Data | Purpose |
|--------|------|---------|
| Polymarket API | Market prices, order book depth, volume | Current market pricing |
| Deribit API | Options chain (strikes, IVs, prices) | Implied probability distribution |
| Binance/Coinbase | Spot + perp prices, funding rates | Current price reference |
| On-chain (Glassnode / free alternatives) | Large transfers, exchange balances | Directional signals |

### Layer 2: Probability Models

**Model A - Options-Implied Probability:**
- Extract risk-neutral probability distribution from Deribit option prices
- Directly compute P(BTC >= $X by date T)
- Highest signal quality: priced by real money from sophisticated traders

**Model B - Monte Carlo Simulation:**
- Input: current price, historical volatility (30d/60d/90d rolling)
- Simulate 100K+ price paths using Geometric Brownian Motion
- Count paths that reach target price by target date
- Output: probability estimate

**Combined Signal:**
- Weighted average of Model A (weight: 0.6) and Model B (weight: 0.4)
- Model A gets higher weight because it reflects real market consensus

### Layer 3: Signal Generation

```
edge = fair_probability - polymarket_price
if abs(edge) > threshold (8-10%):
    direction = BUY_YES if edge > 0 else BUY_NO
    position_size = half_kelly(edge, fair_probability)
    emit signal
```

### Layer 4: Execution

- Phase 1: Manual execution (view signals, place orders manually)
- Phase 2: Semi-auto (alerts via Telegram/Discord, one-click execute)
- Phase 3: Full auto via Polymarket CLOB API

## Implementation Roadmap

### Week 1: Data Foundation + Observation
- Connect Polymarket API, fetch all active crypto markets
- Connect Deribit API, fetch BTC/ETH options chain
- Daily script: output comparison table (Polymarket price vs Deribit implied probability)
- NO trading - observe spread magnitude and frequency

### Week 2: Model MVP
- Implement implied probability extraction from option prices
- Implement Monte Carlo simulation model
- Combine outputs into weighted "fair probability"
- Paper trading: record hypothetical trades based on signals

### Week 3: Live Trading (Small)
- Deploy $500 real capital
- Half-Kelly position sizing (conservative)
- Log every trade: entry rationale, model estimate, market price, outcome

### Week 4: Review + Decision
- Model calibration check: do 70% predictions resolve at ~70%?
- P&L analysis: positive EV after fees?
- Decision: optimize / scale capital / pivot

## Risk Management

| Rule | Limit |
|------|-------|
| Single position max | 5% of total capital |
| Single asset exposure (e.g., all BTC markets) | 30% of total capital |
| Drawdown stop | Pause at 20% drawdown, review model |
| Liquidity filter | Skip markets with thin order books |

## Capital Plan

- Validation phase: $500 - $2,000
- Scaling phase (after 4-week validation): up to $100,000
- Scale only if: model calibration is good AND positive EV after fees

## Key Risks

1. **Model risk**: Our probability estimates could be systematically wrong
2. **Liquidity risk**: Thin markets may cause slippage eating into edge
3. **Correlation risk**: Multiple BTC markets may all move against us simultaneously
4. **Platform risk**: Polymarket resolution disputes, API changes
5. **Regime change**: Crypto volatility regime shifts making historical data less useful
