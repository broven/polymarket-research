## Overview

Detect mispriced crypto price-target markets on Polymarket Global by comparing market prices against probability estimates derived from options-implied path simulation and jump-diffusion Monte Carlo. Trade only when net edge (after dynamically queried costs and uncertainty) is positive.

## Core Thesis

Polymarket crypto markets are largely priced by retail intuition. Professional-grade tools (options-implied barrier probabilities, jump-diffusion simulation) can produce more accurate estimates. The gap between the two, minus actual trading costs, is our edge.

## Target Markets

**Scope: 仅限纯价格市场，排除事件驱动市场。**

Included:
- "Will BTC reach $X by date Y?" (barrier/touch type)
- "Will ETH reach $X by date Y?" (barrier/touch type)
- Price range / bracket markets (terminal value type)

Excluded (不同信号源，单独建策略):
- ETF approvals, protocol upgrades, regulatory actions
- Any market whose resolution depends on non-price events

**市场分类标签**:
- `barrier_up`: 到期前是否向上触达目标价
- `barrier_down`: 到期前是否向下触达目标价
- `terminal_range`: 到期时价格落在某区间

每种类型使用对应的概率计算方法，不可混用。

**市场时长筛选**:
- 优先: 到期 > 24h 的市场（通常 fee-free，成本更低）
- 谨慎: 15 分钟市场（有 fee curve，需确认 edge 能覆盖成本）

### Layer 2: Probability Models

#### Problem Type Distinction (critical)

Polymarket 的 "Will X reach $Y before date T?" 是一个 **first-passage (barrier) 问题**，不是终值问题。

- Barrier 问题: P(max(S_t, 0<=t<=T) >= X) — 路径上任意时刻触达即算
- Terminal 问题: P(S_T >= X) — 仅看到期时刻的价格

Barrier 概率 >= Terminal 概率（永远如此）。用终值概率去估计 barrier 市场会**系统性低估**，产生虚假 edge。

#### Model A - IV Surface Path Simulation (改进)

> v2 用解析 barrier 公式，但在 vol smile + 离散监控下误差大。v2.1 改为路径模拟。

1. 从 Deribit 期权链构建完整隐含波动率曲面 σ_imp(K, T)
2. 在风险中性测度 (Q) 下，用 IV surface 做 **局部波动率路径模拟**:
   - 用 Dupire 公式从 IV surface 提取局部波动率 σ_local(S, t)
   - 模拟 100K+ 条价格路径，每步使用当时价格对应的局部波动率
   - 按 Polymarket 市场规则做**离散采样**判断触达（而非连续 barrier 近似）
3. 输出: Q-measure barrier probability + 置信区间
4. **Q→P 校准** (见下方独立章节)

**为什么不用解析公式**: barrier option 解析解假设常数波动率 + 连续监控，对 crypto 的 vol smile 和 Polymarket 的离散 resolution 都不适用。路径模拟可以精确匹配实际规则。

#### Model B - Jump-Diffusion Monte Carlo

GBM 对 crypto 不适用: 忽略肥尾和价格跳跃，尤其对 barrier 问题偏差更大。

使用 Merton Jump-Diffusion 模型:
```
dS/S = (μ - λk)dt + σdW + JdN

其中:
- σ: 扩散波动率 (从历史数据估计)
- λ: 跳跃频率 (从历史大幅波动统计)
- J: 跳跃幅度 (log-normal 分布, 参数从历史估计)
- N: Poisson 过程
```

模拟流程:
1. 从历史数据估计参数 (σ, λ, μ_J, σ_J)
2. 模拟 100K+ 条价格路径
3. **Barrier 市场**: 检查每条路径是否在到期前触达目标价（离散采样）
4. **Terminal 市场**: 检查到期时价格是否在目标区间
5. 输出: P-measure 概率估计 + 置信区间

#### Q→P Calibration (严格时间切分)

> v2 的校准存在数据泄漏风险。v2.1 加入严格的时间切分。

Deribit 给出的是风险中性概率 (Q)，直接当真实概率交易可能产生"假 alpha"。需要校准到 P-measure。

**数据切分规则 (严格时间序列，不可 shuffle)**:

```
|--- Train ---|--- Validation ---|--- Live ---|
   历史数据       Hold-out 验证       实盘交易
   (不可用于评估)  (仅用于评估校准质量)  (校准函数锁定)
```

- **Train set**: 收集历史已 resolve 的市场数据 (Q_prob, actual_outcome)，拟合校准函数
- **Validation set**: 时间上严格在 train 之后的数据，评估校准质量
- **Live**: 校准函数锁定后上线，定期（每月）用新 resolve 数据做增量更新

**最小样本门槛**:
- Train set: >= 50 笔已 resolve 市场才开始拟合（否则用保守折扣 ×0.85）
- Validation set: >= 20 笔才可评估校准质量
- 校准函数形式: isotonic regression 或 Platt scaling (logistic)

**冷启动策略**: 历史数据不足时:
1. 先用保守固定折扣 (Q × 0.85) 作为安全边际
2. 同时积累 (Q_prob, outcome) 数据对
3. 达到 train 样本门槛后切换到拟合校准

#### Combined Signal

```
P_combined = w_A * P_options_calibrated + w_B * P_jumpdiff

默认权重:
- w_A = 0.6 (期权市场信息更丰富)
- w_B = 0.4 (jump-diffusion 捕捉结构性风险)

当期权市场流动性差时 (bid-ask > 5%): 降低 w_A
当距到期 < 3 天时: 提高 w_A (短期期权定价更准)
```

输出同时包含 **点估计** 和 **不确定性区间** (bootstrap 或模型参数扰动)。

### Layer 3: Signal Generation (Cost-Adaptive, Dynamic Fees)

```python
# 动态费用查询 (per market)
market_fee_bps = query_polymarket_fee(token_id)  # 从 API 实时获取
fee = market_fee_bps / 10000                      # 转换为比例

# 15 分钟加密市场: fee curve 依赖当前价格
# fee 在 price=0.50 时最高 (~1.56%), 在 price→0/1 时趋近 0
if is_short_term_crypto(market):
    fee = get_fee_curve_value(polymarket_price)

# 成本估算
slippage = estimate_slippage(order_size, order_book)  # 从订单簿模拟
spread_cost = (ask - bid) / 2                          # 半个 bid-ask spread
total_cost = fee + slippage + spread_cost

# 若使用 limit order (maker): fee 可能为 0 或有 rebate
# maker 策略可以显著降低成本，但牺牲执行确定性
if execution_mode == MAKER:
    fee = 0  # Global 大部分市场 maker 免费
    total_cost = slippage + spread_cost  # 无 taker fee

# 不确定性缓冲
uncertainty = model_confidence_interval_width / 2

# 净边际
edge_gross = P_combined - polymarket_price
edge_net = abs(edge_gross) - total_cost - uncertainty

# 下单条件: 净边际为正
if edge_net > 0:
    direction = BUY_YES if edge_gross > 0 else BUY_NO
    kelly_fraction = edge_net / (1 - polymarket_price) if direction == BUY_YES else edge_net / polymarket_price
    position_size = quarter_kelly(kelly_fraction, capital)
    emit signal(
        market_id, direction, position_size,
        # 记录完整成本分解用于后续校准
        cost_breakdown={fee, slippage, spread_cost, uncertainty}
    )
```

**成本模型持续校准**: 每笔实盘交易记录 (预估成本, 实际成本)，滚动更新滑点模型。

### Layer 4: Execution

- Phase 1: Manual execution (view signals, place orders manually on Polymarket Global)
- Phase 2: Semi-auto (alerts via Telegram/Discord, one-click execute)
- Phase 3: Full auto via Polymarket Global CLOB API

执行策略选择:
- **Taker**: 即时成交，适合时间敏感的信号，需付 fee（如果市场 fee-enabled）
- **Maker (limit order)**: 0 fee + 可能获得 rebate，但不确定是否成交

所有阶段都记录: 预期成本 vs 实际成本，用于持续校准。

| Rule | Limit |
|------|-------|

## Key Risks

1. **概率类型错配**: barrier vs terminal 混用 → 市场分类标签 + 对应模型
2. **Q→P 校准失败**: 数据不足或泄漏 → 严格时间切分 + 最小样本门槛 + 保守折扣
3. **IV surface 模型误差**: 局部波动率在极端行情下不稳定 → uncertainty buffer + 模型分歧过滤
4. **费用模型错误**: 硬编码 vs 实际费率不一致 → 动态查询 + fail closed
5. **流动性风险**: 薄市场滑点吃掉 edge → 流动性过滤 + 实际成本追踪
6. **相关性风险**: 多个 BTC 市场同向暴露 → 单资产敞口上限 30%
7. **平台风险**: Resolution 争议、API 变更、地理封锁 → 监控 + 后期分散
8. **Regime shift**: Crypto 波动率结构性变化 → 滚动窗口重估参数，异常时暂停
