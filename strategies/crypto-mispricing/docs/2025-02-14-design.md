## Overview

Detect mispriced crypto price-target markets on Polymarket Global by comparing market prices against probability estimates derived from options-implied path simulation and jump-diffusion Monte Carlo. Trade only when net edge (after dynamically queried costs and uncertainty) is positive.

## Core Thesis

Polymarket crypto markets are largely priced by retail intuition. Professional-grade tools (options-implied barrier probabilities, jump-diffusion simulation) can produce more accurate estimates. The gap between the two, minus actual trading costs, is our edge.

## Target Markets

**Scope: 仅限纯价格市场，排除事件驱动市场。**

Included:
- "Will BTC reach $X by date Y?" (barrier/touch type)
- "Will ETH reach $X by date Y?" (barrier/touch type)
- Price range / bracket markets (terminal value type)

Excluded (不同信号源，单独建策略):
- ETF approvals, protocol upgrades, regulatory actions
- Any market whose resolution depends on non-price events

**市场分类标签**:
- `barrier_up`: 到期前是否向上触达目标价
- `barrier_down`: 到期前是否向下触达目标价
- `terminal_range`: 到期时价格落在某区间

每种类型使用对应的概率计算方法，不可混用。

**市场时长筛选**:
- 优先: 到期 > 24h 的市场（通常 fee-free，成本更低）
- 谨慎: 15 分钟市场（有 fee curve，需确认 edge 能覆盖成本）

### Layer 2: Probability Models

#### Problem Type Distinction (critical)

Polymarket 的 "Will X reach $Y before date T?" 是一个 **first-passage (barrier) 问题**，不是终值问题。

- Barrier 问题: P(max(S_t, 0<=t<=T) >= X) — 路径上任意时刻触达即算
- Terminal 问题: P(S_T >= X) — 仅看到期时刻的价格

Barrier 概率 >= Terminal 概率（永远如此）。用终值概率去估计 barrier 市场会**系统性低估**，产生虚假 edge。

#### Model A - IV Surface Path Simulation (改进)

> v2 用解析 barrier 公式，但在 vol smile + 离散监控下误差大。v2.1 改为路径模拟。

1. 从 Deribit 期权链构建完整隐含波动率曲面 σ_imp(K, T)
2. **无套利校验 (fail-closed)**:
   - Calendar spread 检查: 同 strike 不同到期，远期 IV 不应系统性低于近期（否则存在 calendar arbitrage）
   - Butterfly spread 检查: 相邻三个 strike 的 call 价格必须满足凸性约束（C(K-dK) + C(K+dK) >= 2*C(K)）
   - 若校验失败: **该到期日/strike 区域标记为不可信，Model A 对该市场降权或跳过**（fail-closed，不输出可能错误的概率）
   - 轻微违反 (< 1 bps): 用插值平滑修复后继续
3. 在风险中性测度 (Q) 下，用 IV surface 做 **局部波动率路径模拟**:
   - 用 Dupire 公式从 IV surface 提取局部波动率 σ_local(S, t)
   - 数值稳定性约束: σ_local 必须 > 0 且 < 合理上限（如 500%）；出现负值或爆炸时用邻近节点插值替代
   - 模拟 100K+ 条价格路径，每步使用当时价格对应的局部波动率
   - 按 Polymarket 市场规则做**离散采样**判断触达（而非连续 barrier 近似）
4. 输出: Q-measure barrier probability + 置信区间
5. **Q→P 校准** (见下方独立章节)

**为什么不用解析公式**: barrier option 解析解假设常数波动率 + 连续监控，对 crypto 的 vol smile 和 Polymarket 的离散 resolution 都不适用。路径模拟可以精确匹配实际规则。

#### Model B - Jump-Diffusion Monte Carlo

GBM 对 crypto 不适用: 忽略肥尾和价格跳跃，尤其对 barrier 问题偏差更大。

使用 Merton Jump-Diffusion 模型:
```
dS/S = (μ - λk)dt + σdW + JdN

其中:
- σ: 扩散波动率 (从历史数据估计)
- λ: 跳跃频率 (从历史大幅波动统计)
- J: 跳跃幅度 (log-normal 分布, 参数从历史估计)
- N: Poisson 过程
```

模拟流程:
1. 从历史数据估计参数 (σ, λ, μ_J, σ_J)
2. 模拟 100K+ 条价格路径
3. **Barrier 市场**: 检查每条路径是否在到期前触达目标价（离散采样）
4. **Terminal 市场**: 检查到期时价格是否在目标区间
5. 输出: P-measure 概率估计 + 置信区间

#### Q→P Calibration (严格时间切分)

> v2 的校准存在数据泄漏风险。v2.1 加入严格的时间切分。

Deribit 给出的是风险中性概率 (Q)，直接当真实概率交易可能产生"假 alpha"。需要校准到 P-measure。

**数据切分规则 (严格时间序列，不可 shuffle)**:

```
|--- Train ---|--- Validation ---|--- Fixed OOS Test ---|--- Live ---|
   历史数据       Hold-out 验证       永久测试集             实盘交易
   (用于拟合)     (用于选模型)        (永不回灌，检测退化)    (锁定函数)
```

- **Train set**: 收集历史已 resolve 的市场数据 (Q_prob, actual_outcome)，拟合校准函数
- **Validation set**: 时间上严格在 train 之后的数据，用于模型选择和超参调优
- **Fixed OOS Test set**: 时间上在 validation 之后，**永不回灌到 train 或 validation**。用于检测校准函数是否退化。每次校准更新后必须在此集上重新评估
- **Live**: 校准函数锁定后上线

**增量更新规则**:
- 每月用新 resolve 数据扩充 train set（旧 validation 可降级为 train）
- **Fixed OOS Test set 永不回灌**，只追加新数据（最近 N 笔 resolve）
- 若 Fixed OOS Test set 上 Brier Score 连续 2 个月恶化 → 触发校准重建

**最小样本门槛**:
- Train set: >= 50 笔已 resolve 市场才开始拟合（否则用保守折扣 ×0.85）
- Validation set: >= 20 笔才可评估校准质量
- Fixed OOS Test set: >= 15 笔（不足时不可声称校准有效）
- 校准函数形式: isotonic regression 或 Platt scaling (logistic)

**冷启动策略**: 历史数据不足时:
1. 先用保守固定折扣 (Q × 0.85) 作为安全边际
2. 同时积累 (Q_prob, outcome) 数据对
3. 达到 train 样本门槛后切换到拟合校准

#### Combined Signal (数据驱动权重)

**冷启动（数据不足时）**:
```
w_A = 0.6, w_B = 0.4  # 启发式默认值
```

**数据驱动更新（积累足够 resolve 数据后）**:

每月用最近 N 笔已 resolve 交易的 Brier Score 反比加权:
```python
brier_A = brier_score(model_A_predictions, outcomes)  # 近期 Model A 表现
brier_B = brier_score(model_B_predictions, outcomes)  # 近期 Model B 表现

# 反比加权: 表现好的模型获得更高权重
inv_A = 1 / (brier_A + epsilon)
inv_B = 1 / (brier_B + epsilon)
w_A = inv_A / (inv_A + inv_B)
w_B = inv_B / (inv_A + inv_B)

# 安全约束: 任一模型权重不低于 0.15，防止完全依赖单模型
w_A = clip(w_A, 0.15, 0.85)
w_B = 1 - w_A
```

**条件修正（叠加在数据驱动权重上）**:
- 期权市场流动性差时 (bid-ask > 5%): w_A *= 0.5, 重新归一化
- Model A 无套利校验失败时: w_A = 0, w_B = 1（完全依赖 Model B）

**切换门槛**: 从启发式切换到数据驱动需 >= 30 笔已 resolve 且两个模型都有预测记录。

输出同时包含 **点估计** 和 **不确定性区间** (bootstrap 或模型参数扰动)。

### Layer 3: Signal Generation (Cost-Adaptive, Dynamic Fees)

**Taker 和 Maker 是两套独立的成本模型，不可混用。**

```python
# ============================================================
# 动态费用查询 (per market)
# ============================================================
market_fee_bps = query_polymarket_fee(token_id)  # 从 API 实时获取

# 15 分钟加密市场: fee curve 依赖当前价格
# fee 在 price=0.50 时最高 (~1.56% / 156 bps), 在 price→0/1 时趋近 0
if is_short_term_crypto(market):
    market_fee_bps = get_fee_curve_bps(polymarket_price)

# ============================================================
# Taker 成本模型 (市价单，确定成交)
# ============================================================
def taker_cost(order_size, order_book, market_fee_bps, price):
    fee = market_fee_bps / 10000
    slippage = estimate_slippage(order_size, order_book)  # 订单簿模拟
    spread_cost = (ask - bid) / 2                          # 半 spread (crossing)
    return fee + slippage + spread_cost

# ============================================================
# Maker 成本模型 (限价单，不确定是否成交)
# ============================================================
def maker_cost(order_size, order_book, market_fee_bps, price, time_to_expiry):
    fee = 0  # Global 大部分市场 maker 免费
    rebate = query_maker_rebate(token_id)  # 可能为正 (收到 rebate)

    # Maker 不 cross spread，但有未成交风险
    fill_prob = estimate_fill_probability(
        order_size, order_book, time_to_expiry
    )  # 基于历史 fill rate 和订单簿形态

    # 未成交的机会成本: edge 可能在等待期间消失
    opportunity_cost = (1 - fill_prob) * expected_edge_decay(time_to_expiry)

    # Maker 的期望成本 = 成交时成本 * 成交概率 + 未成交机会成本
    cost_if_filled = max(fee - rebate, 0)  # rebate 可能覆盖 fee
    expected_cost = fill_prob * cost_if_filled + opportunity_cost
    return expected_cost, fill_prob

# ============================================================
# 执行模式选择
# ============================================================
taker_total = taker_cost(order_size, order_book, market_fee_bps, price)
maker_total, fill_prob = maker_cost(order_size, order_book, market_fee_bps, price, tte)

# 选择期望成本更低的模式
if maker_total < taker_total and fill_prob > 0.5:
    total_cost = maker_total
    exec_mode = MAKER
else:
    total_cost = taker_total
    exec_mode = TAKER

# ============================================================
# 不确定性缓冲 + 信号
# ============================================================
uncertainty = model_confidence_interval_width / 2

edge_gross = P_combined - polymarket_price
edge_net = abs(edge_gross) - total_cost - uncertainty

if edge_net > 0:
    direction = BUY_YES if edge_gross > 0 else BUY_NO
    kelly_fraction = edge_net / (1 - polymarket_price) if direction == BUY_YES else edge_net / polymarket_price
    position_size = quarter_kelly(kelly_fraction, capital)
    emit signal(
        market_id, direction, position_size, exec_mode,
        cost_breakdown={
            'exec_mode': exec_mode,
            'fee_bps': market_fee_bps,
            'taker_cost': taker_total,
            'maker_cost': maker_total,
            'fill_prob': fill_prob,
            'chosen_cost': total_cost,
            'uncertainty': uncertainty,
        }
    )
```

**成本模型持续校准**:
- 每笔实盘交易记录 (预估成本, 实际成本, exec_mode)
- Taker 和 Maker 分别维护各自的滑点/fill rate 模型
- Maker rebate 金额每日从 API 拉取，不用历史值硬编码
- 若某市场 rebate 政策变更（检测到 rebate 偏差 > 20%），触发 maker 成本模型重校准

### Layer 4: Execution

- Phase 1: Manual execution (view signals, place orders manually on Polymarket Global)
- Phase 2: Semi-auto (alerts via Telegram/Discord, one-click execute)
- Phase 3: Full auto via Polymarket Global CLOB API

执行策略选择:
- **Taker**: 即时成交，适合时间敏感的信号，需付 fee（如果市场 fee-enabled）
- **Maker (limit order)**: 0 fee + 可能获得 rebate，但不确定是否成交

所有阶段都记录: 预期成本 vs 实际成本，用于持续校准。

#### 总体指标

| 指标 | 门槛 | 说明 |
|------|------|------|
| 已 resolve 交易数 | >= 50 笔 | 确保统计功效 |
| Q→P 校准数据 | train >= 50, val >= 20, OOS >= 15 | 不可重叠，严格时间切分 |

| 成本模型误差 | MAE < 50 bps (taker), fill rate MAE < 10% (maker) | 分 exec_mode 评估 |
| Sharpe ratio (annualized) | > 0.5 | 风险调整收益 |

#### 分层指标 (按市场子类)

**防止"总体过关但子策略亏损"**。每个活跃子类必须单独达标才可放大该子类的资金:

| 子类 | 最小样本 | Brier Score 门槛 | 净 P&L |
|------|----------|------------------|--------|
| `barrier_up` | >= 15 笔 | < 0.22 | > 0 |
| `barrier_down` | >= 15 笔 | < 0.22 | > 0 |
| `terminal_range` | >= 15 笔 | < 0.22 | > 0 |

- 若某子类样本不足 15 笔: 该子类**不可放大资金**，继续小额运行积累数据
- 若某子类 Brier > 0.22 或 P&L < 0: 该子类**暂停交易**，排查模型问题
- 总体门槛和分层门槛必须**同时满足**

未达标: 继续小资金运行 + 优化模型，不放大。

## Risk Management

| Rule | Limit |
|------|-------|
| Single position max | 5% of total capital |
| Single asset exposure (all BTC markets combined) | 30% of total capital |
| Drawdown stop | Pause at 15% drawdown, mandatory review |
| Liquidity filter | Skip markets where estimated slippage > 1% |
| Model disagreement | Skip if Model A and B estimates differ > 20% |
| Minimum edge | Only trade when edge_net > 0 (after all actual costs) |
| Fee check | Reject trade if fee_rate_bps cannot be queried (fail closed) |

## Key Risks

1. **概率类型错配**: barrier vs terminal 混用 → 市场分类标签 + 对应模型
2. **Q→P 校准失败**: 数据不足或泄漏 → 严格时间切分 + 最小样本门槛 + 保守折扣
3. **IV surface 模型误差**: 局部波动率在极端行情下不稳定 → uncertainty buffer + 模型分歧过滤
4. **费用模型错误**: 硬编码 vs 实际费率不一致 → 动态查询 + fail closed
5. **流动性风险**: 薄市场滑点吃掉 edge → 流动性过滤 + 实际成本追踪
6. **相关性风险**: 多个 BTC 市场同向暴露 → 单资产敞口上限 30%
7. **平台风险**: Resolution 争议、API 变更、地理封锁 → 监控 + 后期分散
8. **Regime shift**: Crypto 波动率结构性变化 → 滚动窗口重估参数，异常时暂停
